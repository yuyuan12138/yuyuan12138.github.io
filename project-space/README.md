# yuyuan12138.github.io — personal blog (project space)

## What this is
The personal blog of Ruojun Wang at <https://yuyuan12138.github.io>, served by
GitHub Pages from the `gh-pages` branch (this repo's only branch). A
hand-built editorial static site — no Hexo/Jekyll source: pages are
hand-authored HTML under `content/`, the design system lives in `design/`, and
`tools/build_blog.py` generates everything else. Everything at the repo root
outside the source dirs is build output.

`project-space/` (this directory) is the project's docs layer — tracked in git
but **not part of the built site**: `tools/build_blog.py` wipes its output dir
(`tools/build_blog.py:238`) and writes only an explicit allowlist of paths
(five byte-identical copies from `content/` + `design/` at `:241-250`, then
generated article/tag/404/redirect/atom files); `project-space/` appears
nowhere in the script and none of these files is linked from any served page.
(Nuance: GitHub Pages serves whatever is committed to the branch, so this dir
is technically reachable at its URL — it is simply never emitted by the build
and never linked.)

## How it works
`tools/build_blog.py` copies hand-authored pages from `content/` and
`design/style.css` byte-identical, then generates article pages from the
`POSTS` + `PROSE` dicts, tag pages, 404, old-slug redirects and `atom.xml`.
The design rationale lives in `design/DESIGN.md` (198 lines) — it serves as
this project's architecture doc; no separate architecture.md was created
(retrofit rule: index-in-place, nothing moves).

## Conventions
- Docs describe; live files own. Docs work never edits site sources or build
  output; the docs layer records decisions and operations with citations.
- Decisions: append-only ADRs in `project-space/docs/decisions.md` (newest last,
  never edited after writing).
- Dispatch records: `project-space/work/<date>-<slug>/RECORD.md`, append-only.
- Publishing: follow `project-space/docs/runbooks/publishing.md` — a post is a
  POSTS dict entry + hand-authored PROSE HTML; homepage/archives must be
  hand-edited or the post stays undiscoverable; the build diff must stay
  confined to site files.
- Rebuild: `python3 tools/build_blog.py [outdir]`; hand-authored sources are
  copied byte-identical — edit sources, never the root copies.
- Every number/claim in docs cites a file or commit id; unverifiable claims are
  marked "unverified", never guessed.
- Git: stage explicit paths only (never `git add -A`/`git add .`); this branch
  IS the published site — `git push` happens only as the runbook's deploy step.
